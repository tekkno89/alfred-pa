# Triage v3.3 Bug Fixes and UX Improvements

**Date:** 2026-05-24
**Status:** Draft

## Overview

Four targeted fixes to the Triage v3.3 implementation:
1. Transparency API 500 error (missing DB columns)
2. Wizard role/goals redesign with separate steps and custom goals
3. Message types not saved after wizard completion
4. Active Hours UI layout issues

## Issue 1: Transparency API 500 Error

### Problem
The `/api/triage/transparency/keywords` endpoint returns 500 error due to missing `created_at` and `updated_at` columns in the `topic_affinities` table.

### Root Cause
`TopicAffinity` model inherits from `TimestampMixin` which expects these columns, but the database table was created before the mixin was added.

### Solution
Create Alembic migration to add missing columns:
```sql
ALTER TABLE topic_affinities ADD COLUMN created_at TIMESTAMP WITH TIME ZONE DEFAULT now();
ALTER TABLE topic_affinities ADD COLUMN updated_at TIMESTAMP WITH TIME ZONE DEFAULT now();
```

### Files
- `backend/alembic/versions/054_add_topic_affinities_timestamps.py` (new)

## Issue 2: Wizard Role/Goals Redesign

### Problem
Current wizard has hardcoded goal options on the same step as role entry. Users want:
1. Separate steps for role and goals
2. LLM-generated goal options based on role
3. Ability to add custom goals

### Solution

#### New Flow (6 steps)
1. **Step 1 - Role:** Text input for user's role
2. **Step 2 - Goals:** 
   - LLM generates 4-6 goal options based on role
   - User selects multiple from generated options
   - User can add custom goals via text input + "Add" button
   - Custom goals appear as additional selectable chips
3. **Step 3 - Questions:** LLM generates questions based on role + selected goals
4. **Step 4 - Message Types:** LLM-suggested types, user selects
5. **Step 5 - Calibration:** Optional Slack link examples
6. **Step 6 - Review:** Edit P0-P3 definitions, apply

#### API Changes
Add new endpoint:
```
POST /api/triage/wizard/generate-goals
Request: { "role": "Engineering manager at a startup" }
Response: { "goals": ["Stay on top of production incidents", "Reduce noise from automated messages", ...] }
```

#### Frontend Changes
- Update `ClassifierWizardModal` to 6 steps
- Add goal generation step with loading state
- Add custom goal input with "Add" button
- Pass all selected goals (generated + custom) to question generation

### Files
- `backend/app/api/triage_wizard.py` - add `generate_goals` endpoint
- `backend/app/schemas/triage.py` - add `WizardGoalsRequest`, `WizardGoalsResponse` schemas
- `frontend/src/components/triage/ClassifierWizardModal.tsx` - 6-step flow with custom goals
- `frontend/src/hooks/useTriage.ts` - add `useGenerateWizardGoals` hook
- `frontend/src/types/index.ts` - add `WizardGoal` type

## Issue 3: Message Types Not Saved After Wizard

### Problem
Wizard suggests message types and user can select them, but they're never saved to the database.

### Root Cause
`onApply` callback in `TriageSettingsPage.tsx` only saves priority definitions, not the selected message types.

### Solution
1. Update `ClassifierWizardModal` to pass selected message types to `onApply`
2. Update `TriageSettingsPage` to save message types via the existing message types API

#### Implementation Details
```typescript
// ClassifierWizardModal.tsx
interface ClassifierWizardModalProps {
  onApply: (definitions: PriorityDefinitions, messageTypes: MessageTypeSuggestion[]) => void
}

// TriageSettingsPage.tsx
onApply={(defs, messageTypes) => {
  // Save priority definitions
  updateSettings.mutate({ p0_definition: defs.p0_definition, ... })
  
  // Save message types
  messageTypes.forEach(type => {
    createMessageType.mutate({
      type_name: type.type_name,
      type_definition: type.type_definition,
    })
  })
}}
```

### Files
- `frontend/src/components/triage/ClassifierWizardModal.tsx` - pass message types to onApply
- `frontend/src/pages/TriageSettingsPage.tsx` - save message types

## Issue 4: Active Hours UI Layout

### Problem
The 7-column grid for active hours has fixed-height containers that cut off time pickers when hours span late times (e.g., 09:00-23:00).

### Root Cause
Grid uses fixed padding/height that doesn't account for content overflow.

### Solution
Keep the 7-column grid for alignment but allow rows to auto-size:
```tsx
<div className="grid grid-cols-7 gap-2 auto-rows-auto">
  {/* Day containers */}
  <div className="p-3 rounded-lg border min-h-fit">
    {/* Time pickers with no height constraint */}
  </div>
</div>
```

Key changes:
1. Add `auto-rows-auto` to grid container
2. Add `min-h-fit` to day containers
3. Remove any fixed heights from time picker containers

### Files
- `frontend/src/components/triage/ActiveHoursCard.tsx` - fix layout
